Repurpose vibeclaw's P2P inference layer into an agensis feature.

Source (almostnode_manager / vibeclaw.dev):
- src/forge/mesh-client.ts   — browser WS mesh node: auth w/ token, advertise ModelInfo[],
                               register InferenceHandler, fulfill_request -> fulfill_response.
- src/forge/mesh-types.ts    — WS message + payload types, ModelInfo, crumb/cheese economy.
- relay/server.mjs           — dumb token-gated WS byte-bridge (browser <-> external, 2 slots).
- index.html:1944-1955       — real in-browser WebGPU inference via @mlc-ai/web-llm (WebLLM/MLC).
- examples/openclaw-webgpu-demo.html:502-507 — @huggingface/transformers webgpu path.

Goal: an agensis agent/CLI user can run a container IN A BROWSER to (a) share their WebGPU /
local models, or (b) proxy their existing models (Ollama/LM Studio/gateway), INTO the agensis
mesh, so those models become usable by agensis agents and by OpenAI-compatible clients.

Constraint from advisor review:
- Mesh fulfill protocol is single-shot {prompt,systemPrompt,maxTokens} — NOT a streaming
  Messages/tool_use API. A ~1.5-8B browser model cannot drive a frontier coding-agent loop.
  So: share-WebGPU = gateway + cheap/non-coding sub-tasks; proxy-existing (bigger local model)
  = can back a LOCAL agent. Do not headline "frontier coding on a shared browser model".
- Reuse agensis's own rails (register_agent kinds/tokens, capability-drift heartbeat, WS
  transport, agent_connections.capabilities jsonb). Do NOT port vibeclaw's burrow server or
  crumb economy wholesale.

Deliverable: phased implementation plan (data model, transport, gateway API, browser asset,
consumer wiring, security), grounded in the current agensis architecture. Planning only, no code.
