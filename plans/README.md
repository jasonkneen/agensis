## Dependency notes

None of the 10 plans hard-depend on one another — each was deliberately scoped to be independently
executable and verifiable. Soft relationships worth knowing about when sequencing work:

- **002 (stored XSS) and 005 (token revocation) compound**: 002's impact analysis assumes a stolen
  token grants indefinite access (005's finding). Landing 005 first reduces 002's worst-case blast
  radius, but 002 is the more urgent fix (the live exploitation path) — do not delay 002 waiting on
  005.
- **006 and the "three migration directories" systemic issue**: 006 fixes the concrete drift found
  during this review; it does not fix the broader "no doc says which schema source is canonical"
  problem (that's a DX finding not yet turned into its own plan — see below). Whoever executes 006
  should not attempt to solve the broader doc gap as part of it (out of scope per 006's own Scope
  section).
- **004 and 005 both touch auth** but are independent: 004 is about password strength and
  throttling; 005 is about token lifetime and revocation. Either can land first.

## 2026-07-04 performance round (plans 011–016)

Focused perf audit (render performance / network chatter / bundle & load path, three parallel
subagents, every table claim re-verified against live source before planning). Headline findings:
the Electron shell (94 lines, sandboxed, loads the built bundle from disk) is NOT the problem —
the web app is. Four compounding causes: (1) per-SSE-token `setMessages` at App root with zero
`React.memo` anywhere in `src/components` re-renders the entire app per streamed token, and
`MarkdownContent` re-parses every message per render — O(messages × tokens); (2) always-on realtime
chatter — 2s full-window presence snapshots and ~31Hz cursor broadcasts even solo, plus no-op prune
ticks re-rendering the whole tree every 1.5s while idle; (3) the PWA precaches ~10.7MB including
runtime-lazy mermaid/katex/cytoscape chunks and the 724KB dev-only Showcase gallery; (4) 8.6MB
unoptimized background JPGs and a render-blocking 6-family Google Fonts `@import`.

Dependency notes for this round:
- 011/012 cut render **frequency**; 016 cuts render **cost** — 016 lists 011/012 as soft
  dependencies only for cleaner before/after profiling; any order works.
- 013/014/015 are independent build/asset fixes; land any time.

Perf findings from this round NOT yet planned (evidence gathered, ask for plans in a future round):
- **[NET-01] Cold-load waterfall**: auth → workspaces → ~15 parallel workspace-scoped hook fetches
  (~18 round-trips to fly.dev before usable UI). Fix = one `/backend/workspace/bootstrap` snapshot
  endpoint seeding all hooks. Biggest cold-start win; L effort, needs backend design.
- **[BUNDLE-03] Lazy-load window/dialog components**: 1.2MB main chunk because every window type is
  eagerly imported in App.tsx; React.lazy per surface. L effort, MED risk (Suspense in dialogs).
- **[NET-05/06] Unbounded fetches**: messages `select('*')` with no limit (full transcript per chat
  open, one per open chat window — N+1), documents list pulling full doc bodies for a title list.
- **[NET-07] Workspace-wide `messages` subscription in `useAgentStatusFeed`** streams every row incl.
  ~1/s agent "thinking" heartbeats to every client for one sidebar bubble; needs a lightweight
  server-side `agent_status` broadcast instead.
- **[NET-04] `useAgentConnections` 15s HTTP poll** duplicating its own realtime subscription —
  verify heartbeat UPDATEs ride realtime, then drop the poll.
- **[NET-08] `getSystemCapabilities`** re-runs a daemon filesystem scan on every workspace/layer
  switch; cache per path with a short TTL.

this directory, or re-run the `improve` skill's `reconcile` mode once the codebase has moved).

**Performance**
- ~~Chat message bubbles unmemoized / markdown re-parse per render~~ → now planned (011, 016).
- No code-splitting — every window type loaded eagerly (partially addressed by 013's vendor split
  + Showcase removal; per-window React.lazy remains unplanned — see BUNDLE-03 above).
- ~~Unoptimized background images~~ → now planned (014).
- Agent memory list does `select('*')` including full file content for a metadata-only view.

**Tech debt & architecture**

  substantially since the last review instead of being decomposed further.
- `useMemoryFileComments` duplicates `useRealtimeComments` line-for-line.
- Neo-brutalist theme reaches into shadcn component internals via ~246 attribute selectors with no
  compiler-checked link to the components it themes.

**Dependencies**

  staged migration).
- `shadcn` CLI shipped in `dependencies` not `devDependencies`, never imported.
- `@open-pets/client` installed, zero imports anywhere.

  plus still-dual lockfile.

  trivial, just needs `npm install` and a note about when that's required.

**DX & tooling**

  while `package.json` says 19.
- Three migration-of-truth locations with no doc naming the canonical one (systemic version of
  plan 006's concrete fix).
- ~8MB of test artifacts (`.agensis_uploads/`, `.playwright-mcp/`) committed to git, not gitignored.
- Env vars required for split Netlify+Fly deploys undocumented outside a code comment.
